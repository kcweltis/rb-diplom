# 4.1 Описание веб-приложения

## 4.1.1 Описание динамического контента веб-приложения

Веб-приложение «Русские блины» представляет собой полнофункциональную систему управления доставкой и продажей кулинарных изделий, которая интенсивно использует динамический контент, получаемый из базы данных «PostgreSQL». Приложение построено на архитектуре «MVC», где контроллеры обрабатывают запросы пользователя, извлекают данные из базы и передают их в представления для отрисовки.

Динамический контент реализуется на двух уровнях:

**На серверной стороне:** Шаблонизатор «EJS» отрисовывает «HTML»-страницы с данными из базы данных, позволяя отображать персонализированную информацию для каждого пользователя в реальном времени.

**На клиентской стороне:** «JavaScript»-скрипты обеспечивают интерактивность, асинхронные запросы к серверу и динамическое обновление содержимого без перезагрузки страницы.

### Основные страницы с динамическим контентом

**Главная страница** — содержит динамический баннер-слайдер с изображениями из базы данных и список рекомендуемых товаров, которые загружаются по запросу из таблицы «featured_products». Слайдер автоматически переключается между баннерами, каждый из которых может быть активирован администратором.

**Страница меню** — выводит все доступные товары, сгруппированные по категориям. Товары загружаются динамически из базы данных с учетом статуса активности. Страница поддерживает поиск по названию блюда, при котором список товаров фильтруется на сервере. Активная категория при скролле выделяется в боковой навигации благодаря «JavaScript»-скрипту отслеживания видимости элементов.

**Карточка товара** — отображает полную информацию о блюде, включая описание, цену, пищевую ценность (белки, жиры, углеводы, калории), доступные размеры с разными ценами и список добавок. Похожие товары из той же категории загружаются случайно и предлагаются пользователю для дополнительного выбора.

**Калькулятор калорий** — интерактивная страница, позволяющая пользователям выбирать товары и видеть суммарную калорийность выбранного набора блюд. Все товары с информацией о пищевой ценности загружаются на страницу при её загрузке.

**Страница акций и новинок** — выводит активные акции и новости, которые администратор может добавлять и удалять. Каждая акция может содержать изображение, описание и порядок сортировки. На этой странице также расположена форма для подписки на рассылку новостей.

**Личный кабинет пользователя** — отображает информацию о профиле пользователя и полную историю заказов с указанием статуса, суммы, даты, типа (доставка или самовывоз) и списка товаров в каждом заказе. Данные загружаются в соответствии с идентификатором пользователя из сессии.

**Страница корзины** — выводит все товары, добавленные пользователем, с возможностью изменения количества, удаления товаров и просмотра итоговой стоимости. Итоговая цена рассчитывается динамически с учетом выбранных размеров, добавок и количества товаров.

**Форма оформления заказа** — позволяет указать данные заказа (имя, номер телефона, адрес доставки), выбрать тип доставки или самовывоза, способ оплаты (наличные или онлайн). При выборе доставки автоматически рассчитывается стоимость доставки по формуле (10 % от суммы заказа, но не менее 150 и не более 500 рублей).

**Админ-панель** — включает несколько подразделов для управления различными аспектами приложения: управление товарами (создание, редактирование, удаление с загрузкой изображений), управление категориями, управление добавками, управление баннерами, управление акциями и новостями, просмотр статистики (количество пользователей, заказов, товаров).

**Кабинет курьера** — мобильный интерфейс для работников доставки, который выводит список доступных заказов, готовых к доставке, информацию об активном заказе текущего курьера (имя и номер телефона клиента, адрес доставки, сумма заказа, количество позиций) и статистику по заказам за день (количество доставленных заказов, заработанная сумма).

**Чат-помощник** — интеллектуальный помощник, который рекомендует товары на основе запросов пользователя. Ответы генерируются с использованием « HTML »-тегов и включают кнопки для добавления рекомендуемых товаров в корзину прямо из чата.

### Основные функциональные файлы

Контроллеры в папке «src/controllers/» содержат бизнес-логику для каждого раздела приложения. Контроллер «home.controller.js» загружает данные для главной страницы. Контроллер «menu.controller.js» обрабатывает отображение меню и фильтрацию товаров. Контроллер «product.controller.js» выводит информацию о конкретном товаре и похожих товарах. Контроллер «calories.controller.js» подготавливает данные для калькулятора калорийности.

Контроллер «promo.controller.js» управляет акциями и подписками на рассылку. Контроллер «profile.controller.js» отображает информацию профиля и историю заказов пользователя. Контроллер «cart.controller.js» управляет корзиной с динамическим расчетом стоимости. Контроллер «order.controller.js» обрабатывает создание заказов и интеграцию с платежной системой «Yookassa».

Контроллер «admin.controller.js» предоставляет функции для администраторов по управлению товарами, категориями, баннерами и другим содержимым. Контроллер «courier.controller.js» управляет кабинетом курьера и отображением доступных заказов. Контроллер «chat.controller.js» обрабатывает запросы от чата и генерирует ответы с рекомендациями.

Представления в папке «src/views/pages/» содержат шаблоны «EJS» для отрисовки страниц. Каждый шаблон использует встроенный код «EJS» (теги `<% %>`) для итерации по массивам товаров, категорий, заказов и вывода их на страницу. Шаблоны также содержат условные операторы для отображения различных элементов в зависимости от наличия данных.

Клиентские скрипты в папке «src/public/js/» обеспечивают интерактивность на страницах. Скрипт «menu.js» отслеживает позицию категорий при скролле и активирует соответствующие пункты навигации. Этот же скрипт загружает информацию о товаре через «API» и отображает её в модальном окне. Скрипт «calories.js» позволяет фильтровать товары по категориям и вычислять суммарную калорийность. Скрипт «order-tracker.js» отслеживает статус заказа в реальном времени.

Маршруты в папке «src/routes/» определяют соответствие между «URL»-адресами и функциями контроллеров. Файл «web.routes.js» содержит маршруты для публичных страниц, аутентификации и профиля пользователя. Файл «admin.routes.js» содержит маршруты для админ-панели и курьерского кабинета.

Промежуточное ПО в папке «src/middleware/» обеспечивает аутентификацию и авторизацию. Файл «auth.js» проверяет наличие сессии пользователя и убеждается, что доступ к защищённым страницам имеют только авторизованные пользователи. Файл «currentUser.js» присоединяет информацию о текущем пользователе к объекту запроса для передачи в представления.

База данных содержит таблицы для хранения пользователей, товаров, категорий, добавок, заказов, содержимого корзины, баннеров, акций, новостей и других данных. Таблица «products» содержит поле «sizes» в формате «JSON»-массива, позволяя каждому блюду иметь несколько размеров с разными ценами. Таблица «orders» содержит поле «payment_info» для хранения информации о платежах от «Yookassa». Таблица «cart_items» хранит выбранные добавки в «JSON»-формате.

### Механизм реализации динамического контента

Динамический контент загружается согласно следующему процессу: пользователь отправляет запрос к определённому маршруту приложения, маршрут передаёт запрос соответствующему контроллеру, контроллер выполняет запрос к базе данных для получения необходимых данных, полученные данные передаются в представление « EJS », где происходит отрисовка « HTML »-страницы с подставленными данными из базы, готовая « HTML »-страница отправляется клиенту и отображается в браузере.

При изменении данных (например, добавление товара в корзину) «JavaScript»-скрипты выполняют асинхронный запрос на сервер, сервер обновляет данные в базе и возвращает обновленный результат, клиентский скрипт обновляет содержимое страницы без полной перезагрузки.

### Ролевая система

Приложение поддерживает различные уровни доступа на основе ролей пользователя. Обычные пользователи могут просматривать меню, добавлять товары в корзину, оформлять заказы, просматривать свой профиль и историю заказов. Администраторы имеют доступ к панели управления, где могут создавать, редактировать и удалять товары, категории, баннеры, акции и просматривать статистику по пользователям и заказам. Курьеры имеют доступ к специализированному мобильному интерфейсу для просмотра доступных заказов, управления активным заказом и отслеживания статистики доставок.

### Технологии реализации

Динамический контент реализуется с использованием «Node.js», «Express.js», «EJS» и «PostgreSQL». «Node.js» предоставляет среду выполнения для серверных «JavaScript»-скриптов. «Express.js» обеспечивает маршрутизацию и обработку «HTTP»-запросов. «EJS» выполняет отрисовку «HTML»-страниц с подставленными данными. «PostgreSQL» хранит все данные приложения и поддерживает формат «JSONB» для гибкого хранения сложных структур данных.

На клиентской стороне используется чистый «JavaScript» для создания интерактивных элементов, таких как слайдеры, модальные окна, фильтрация данных и асинхронные запросы через «Fetch API». Также используется «Multer» для загрузки файлов (изображения товаров, баннеры, фотографии отзывов) на сервер.

## 4.2 Логика работы веб-приложения

### 4.2.1 Описание укрупненного алгоритма

Архитектура веб-приложения построена на иерархической структуре модулей и функциональных файлов, которые взаимодействуют друг с другом для обеспечения полного функционала доставки и продажи кулинарных изделий. На рисунке 4.1 представлена архитектура приложения, показывающая иерархические зависимости между всеми компонентами.

Верхний уровень структуры представляет точка входа приложения — файл «app.js», который инициализирует сервер и подключает все необходимые модули. Из главного файла приложения выходят две основные ветки маршрутизации: веб-маршруты для публичных страниц и маршруты для админ-панели и курьерского кабинета.

**Модуль аутентификации и авторизации** включает контроллер «auth.controller.js», который обрабатывает регистрацию, вход, логаут и восстановление пароля. Этот модуль использует сервис «user.service.js» для работы с пользователями и сервис «otp.service.js» для двухфакторной аутентификации. Входная информация включает учетные данные пользователя, а выходная — данные сессии и информация о пользователе.

**Модуль главной страницы** состоит из контроллера «home.controller.js» и представления «home.ejs». Контроллер получает на входе запрос клиента, загружает избранные товары и активные баннеры из базы данных, и передает эти данные в представление для отрисовки. Вызываемые компоненты: база данных для получения товаров и баннеров.

**Модуль меню** включает контроллер «menu.controller.js», представление «menu.ejs» и клиентский скрипт «menu.js». На входе — параметры поиска и фильтрации. На выходе — отсортированные по категориям товары. Контроллер обращается к базе данных для получения категорий и товаров, фильтрует результаты на основе поиска, после чего данные передаются в представление.

**Модуль товара** состоит из контроллера «product.controller.js» и представления «product.ejs». На входе — идентификатор товара из «URL». На выходе — полная информация о товаре, похожие товары и список доступных добавок. Модуль обращается к базе данных для получения информации о товаре, похожих товарах и добавках.

**Модуль калькулятора калорий** включает контроллер «calories.controller.js», представление «calories.ejs» и клиентский скрипт «calories.js». На входе — выбор товаров пользователем. На выходе — суммарная калорийность выбранных блюд. Контроллер загружает все товары с информацией о пищевой ценности.

**Модуль акций и новостей** состоит из контроллера «promo.controller.js» и представления «promotions.ejs». На входе — запрос на получение активных акций. На выходе — список акций, новостей и форма для подписки. Контроллер также обрабатывает подписки на рассылку через сервис отправки писем.

**Модуль профиля пользователя** включает контроллер «profile.controller.js» и представление «profile/index.ejs». На входе — идентификатор пользователя из сессии. На выходе — информация профиля и история заказов пользователя. Модуль обращается к базе данных для получения данных пользователя и всех его заказов с подробной информацией о товарах в каждом заказе.

**Модуль корзины** состоит из контроллера «cart.controller.js» и представления «cart.ejs». На входе — содержимое корзины. На выходе — список товаров с итоговой стоимостью. Контроллер выполняет сложные вычисления с учетом размеров и добавок каждого товара для расчета окончательной цены.

**Модуль заказов** включает контроллер «order.controller.js» и форму оформления заказа. На входе — данные заказа (товары, личная информация, адрес доставки, способ оплаты). На выходе — созданный заказ с присвоенным идентификатором и информацией о платеже. Модуль обращается к платежной системе «Yookassa» для обработки онлайн-платежей и сохраняет информацию о платеже в базе данных.

**Модуль админ-панели** представляет собой комплексную систему управления содержимым веб-приложения, состоящую из контроллера «admin.controller.js» и набора представлений в папке «admin/», включая подшаблоны для различных разделов управления. На входе модуль получает действия администратора (создание, редактирование, удаление товаров, категорий, баннеров, акций), а на выходе генерирует обновленные данные, которые записываются в базу данных. Модуль разделен на несколько функциональных подмодулей: управление товарами (с возможностью загрузки изображений и указания параметров), управление категориями и добавками (для структурирования каталога), управление баннерами (для главной страницы), управление акциями и новостями (для маркетинговых целей) и просмотр статистики (количество пользователей, заказов, выручка). Все операции в админ-панели требуют предварительной аутентификации администратора и проверки его роли через middleware «auth.js». При загрузке изображений используется middleware «Multer», который сохраняет файлы на сервер в директорию «public/uploads/» и возвращает путь для сохранения в базе. Модуль обеспечивает валидацию вводимых данных на сервере перед записью в базу, что предотвращает попадание некорректных или потенциально опасных данных в систему.

**Модуль кабинета курьера** разработан как специализированная система для управления доставками и предоставляет курьерам быстрый доступ к необходимой информации о заказах. Модуль включает контроллер «courier.controller.js» и представления в папке «courier/», содержащие интерфейсы для просмотра доступных заказов, активного заказа и статистики. На входе модуль получает действия курьера (просмотр списка доступных заказов, принятие заказа, обновление статуса доставки), а на выходе предоставляет обновленную информацию о заказе и статистику доставок (количество доставленных заказов за день, общая сумма заработка, средняя стоимость заказа). Модуль обращается к базе данных через запросы «SELECT» для получения информации о доступных заказах (готовых к доставке и не назначенных другим курьерам) и текущих доставках курьера (заказы со статусом «назначен курьеру» или «в пути»). При принятии заказа выполняется операция «UPDATE», которая присваивает заказу идентификатор курьера и изменяет статус. При доставке товара обновляется статус заказа и увеличивается статистика доставленных заказов в таблице статистики курьера. Интерфейс оптимизирован для использования на мобильных устройствах, что позволяет курьерам работать с системой прямо во время доставки.

**Модуль чата** представляет собой интеллектуальный помощник, разработанный для повышения удобства покупателей при выборе товаров. Модуль состоит из контроллера «chat.controller.js», который обрабатывает текстовые запросы пользователей. На входе модуль получает сообщение от пользователя (например, запрос типа «рекомендуй сладкие блины» или «что выбрать на завтрак»), контроллер анализирует текст и выполняет поиск по названиям и описаниям товаров в базе данных. На выходе модуль генерирует ответ с рекомендациями товаров, отформатированный в виде «HTML»-сообщения, которое содержит информацию о товарах (название, описание, цена, изображение) и интерактивные кнопки для быстрого добавления каждого рекомендуемого товара в корзину. Рекомендации основаны на встроенном меню приложения и простом алгоритме соответствия ключевых слов запроса параметрам товаров. Модуль улучшает пользовательский опыт, позволяя покупателям получить персонализированные рекомендации без необходимости самостоятельного просмотра всего каталога, что особенно полезно для новых или нерешительных пользователей.

**Промежуточное ПО** (middleware) в приложении представляет собой набор функций, выполняемых на каждом этапе обработки «HTTP»-запроса, и включает модули аутентификации и авторизации. Файл «auth.js» проверяет наличие активной сессии пользователя в хранилище сессий «PostgreSQL» и убеждается, что доступ к защищённым маршрутам (например, к админ-панели или кабинету курьера) имеют только авторизованные пользователи с соответствующей ролью. Файл «currentUser.js» извлекает информацию о текущем пользователе из сессии и присоединяет её к объекту запроса («req.user»), делая эту информацию доступной для всех контроллеров и представлений без повторной выборки из базы. Middleware «upload.js» использует библиотеку «Multer» для обработки загрузки файлов и сохранения их на сервер с проверкой типа файла и размера. Порядок подключения middleware критически важен: сначала подключаются middleware обработки тела запроса, затем проверки аутентификации и авторизации, и только после этого маршруты приложения. Такая архитектура обеспечивает безопасность приложения, предотвращая несанкционированный доступ к критическим функциям и данным.

**База данных «PostgreSQL»** служит централизованным хранилищем всех данных веб-приложения и состоит из таблиц, спроектированных в соответствии с требованиями системы. Структура базы данных включает таблицы для хранения информации о пользователях (идентификатор, имя, электронная почта, хешированный пароль, роль), товарах (идентификатор, название, описание, цена, категория, размеры в формате «JSON», изображение), категориях и добавках (для структурирования каталога), заказах (идентификатор, пользователь, статус доставки, сумма, информация о платеже), содержимом корзины (товары в корзине, выбранные размеры и добавки), баннерах и акциях (для маркетинговых целей), а также сессиях (для управления авторизацией). Таблица «products» использует поле «sizes» в формате массива «JSON», позволяя каждому блюду иметь несколько размеров с разными ценами без необходимости создания отдельных записей. Таблица «orders» содержит поле «payment_info» в формате «JSON» для хранения информации о платежах от системы «Yookassa», включая статус платежа, идентификатор транзакции и дату платежа. Таблица «cart_items» использует поле «selected_add_ons» для хранения массива выбранных добавок каждого товара. Все модули приложения обращаются к базе данных через контроллеры, выполняя запросы «SELECT» для чтения данных, «INSERT» для создания новых записей, «UPDATE» для изменения существующих данных и «DELETE» для удаления. Для критических операций (например, при создании заказа) используются транзакции, которые обеспечивают целостность данных и позволяют откатить все изменения в случае ошибки. База данных обеспечивает центральное управление данными, их защиту и возможность масштабирования приложения при увеличении объемов данных.

На рисунке 4.1 показана полная иерархия структуры приложения, где стрелки обозначают направление вызовов и передачи данных между компонентами.

### 4.2.2 Описание логики работы каждого модуля

**Логика работы модуля аутентификации** следующая: пользователь заполняет форму регистрации или входа, форма отправляется на сервер к контроллеру аутентификации, контроллер проверяет наличие пользователя в базе данных, если пользователь новый, создается новая запись с хешированным паролем, если пользователь существует, проверяется корректность пароля, при успешной аутентификации создается сессия пользователя, которая сохраняется в базе данных. На рисунке 4.2 показана схема работы модуля аутентификации, где видны этапы проверки учетных данных и создания сессии.

**Логика работы модуля меню** следующая: пользователь открывает страницу меню, контроллер загружает все категории и товары из базы данных, если пользователь вводит текст в поле поиска, контроллер фильтрует товары по названию на сервере, товары группируются по категориям, отправляются в представление, представление отрисовывает категории и товары в виде иерархического списка, клиентский скрипт отслеживает позицию видимой категории при скролле и выделяет соответствующий элемент в боковой навигации. На рисунке 4.3 показана схема работы модуля меню с фильтрацией и синхронизацией навигации.

**Логика работы модуля товара** следующая: пользователь кликает на карточку товара, браузер переходит на страницу товара с передачей идентификатора в «URL», контроллер получает идентификатор из параметров, выполняет запрос к базе для получения информации о товаре, загружает похожие товары случайным образом из той же категории, загружает список доступных добавок, передает все данные в представление, представление отображает товар с полной информацией о пищевой ценности, размерами и добавками. На рисунке 4.4 показана схема загрузки данных товара и похожих товаров.

**Логика работы модуля корзины** следующая: товары хранятся в сессии или в таблице базы данных, когда пользователь открывает страницу корзины, контроллер получает содержимое корзины, для каждого товара выполняются вычисления: если товар имеет выбранный размер, берется цена этого размера вместо стандартной цены, если товар имеет выбранные добавки, их цены суммируются к цене товара, итоговая цена товара умножается на количество, все стоимости суммируются для получения общей стоимости корзины, результаты передаются в представление. На рисунке 4.5 показана схема расчета стоимости корзины с учетом размеров и добавок.

**Логика работы модуля заказов** следующая: пользователь заполняет форму оформления заказа, указывает личные данные, адрес доставки и способ оплаты, форма отправляется контроллеру, контроллер начинает транзакцию в базе данных, создается запись заказа с указанными параметрами, товары переносятся из корзины в таблицу заказа, рассчитывается стоимость доставки по формуле (10% от суммы, минимум 150, максимум 500 рублей), если выбрана онлайн-оплата, заказ отправляется в платежную систему «Yookassa» и создается ссылка на оплату, если выбрана наличная оплата, заказ сразу переводится в статус «готов к доставке», корзина очищается, клиенту отправляется подтверждение по электронной почте. **Логика работы админ-панели** следующая: администратор авторизуется и получает доступ к защищенным страницам, для управления товарами администратор может создавать новые товары с загрузкой изображений, заполнением всех параметров (название, описание, цена, пищевая ценность), указанием размеров и добавок, контроллер проверяет корректность данных, загружает изображение на сервер, сохраняет товар в базе данных, для редактирования товара администратор открывает форму с существующими данными, изменяет нужные поля, контроллер обновляет запись в базе, для удаления товара контроллер проверяет, нет ли ссылок на этот товар в других таблицах, если ссылки существуют, удаление блокируется, иначе товар удаляется.
